# Domain Docs

## Before exploring

- Read `GLOSSARY.md` at the repository root.
- Read decisions in `docs/adr/` relevant to the work.

If these files do not exist, proceed silently. Domain-modeling creates
them lazily when terminology or decisions are resolved.

## Layout

This repository uses a single context:

- `GLOSSARY.md`: domain vocabulary.
- `docs/adr/`: architecture decision records.

## Vocabulary

Use the glossary's terms in issue titles, proposals, hypotheses,
and test names. Reconsider unfamiliar terminology; record real
vocabulary gaps for domain-modeling.

## Decision conflicts

If a proposal contradicts an existing ADR, identify the ADR
and explain why the decision should be reopened.
